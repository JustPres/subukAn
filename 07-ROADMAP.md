# Roadmap

## Validation sequence (must happen before any code)

1. **Paper test** — a one-pager shown to 5–10 people across two groups: potential clients who'd need feedback on a project, and potential testers who'd test for a small fee. Costs nothing, takes a weekend. Goal: see if anyone's eyes actually light up.
2. **Manual pilot, no platform yet** — personally match one client with 3–5 testers. Tasks/questions via a Google Form, screen recording via a free tool, testers paid out of pocket (~₱1,000–2,000 budget). Goal: confirm the core deliverable (real, honest feedback) is something people value enough to pay for again.
3. **Only then, build** — the coded version happens once the manual pilot proves the concept, informed by what was actually learned running it by hand — not before.

## Versioning

- **v0.1** = planning only (this file set). No code exists yet.
- **v0.2** = manual pilot artifacts (forms, manual tracking, no platform code) — output of Step 2 above.
- **v1.0** = first real coded build, scoped by what the manual pilot proved out.

## Backlog — deferred beyond v0.1, do not build yet

These were identified as genuinely useful but out of scope for an early lean MVP. Revisit only once v1.0 has real usage.

| Feature | Why deferred |
|---|---|
| Full persona/demographic tester matching & filtering | Meaningful scope expansion beyond basic profile tags; validate demand for basic matching first |
| A/B / comparative testing (multiple site versions per listing) | Requires supporting multiple assets per listing — real added complexity |
| Accessibility-specialty tester tagging | Strong differentiator, but adds recruitment complexity — worth doing well, not rushed |
| Post-test follow-up / debrief threading between poster and tester | Adds a communication layer beyond accept/reject — nice-to-have, not core |
| Version-over-version benchmark analytics for repeat posters | Needs multiple completed rounds of history to be useful at all |
| First-click / heatmap-style testing | Needs real click-coordinate instrumentation — too heavy for early versions |
| Quick Impression / Five-Second Test | Cheap concept, but needs a different timed-display task format than the core async model — good v1.1 fast-follow |
